# 1366x768 Density Fix — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the "zoomed in" feel at 1366x768 by adjusting layout containers, DataTable density, SlideOverForm sizing, and form typography.

**Architecture:** Layout containers (sidebar, header, padding) shrink at xl to give content more room. DataTable uses width-aware column visibility. SlideOverForm grows at xl. Form labels become lighter/smaller. All changes restore at 2xl.

**Tech Stack:** Next.js 16, Tailwind CSS v4 (CSS-first config), React 19, shadcn/ui

## Global Constraints

- Tailwind v4 CSS-first config — no tailwind.config.js, all tokens in `globals.css` via `@theme inline`
- All spacing follows 4px base grid (Fluent 2 principle)
- shadcn/ui components stay unchanged — only custom feature components are modified
- Run `pnpm lint && pnpm type-check && pnpm test` before committing
- Conventional commits enforced by commitlint

## Task 5: DataTable — Width-Aware Column Visibility

**Files:**
- Modify: `apps/frontend/src/components/data-display/data-table/data-table.tsx`

This task replaces the index-based column visibility with a width-aware algorithm. This is the most complex change.

- [ ] **Step 1: Read the current column visibility logic**

In `data-table.tsx`, find the `useEffect` that sets column visibility (around lines 338-367). It currently uses:
```typescript
if (breakpoint === "sm") {
  visibleCount = 2;
} else if (breakpoint === "md") {
  visibleCount = 3;
} else if (breakpoint === "lg") {
  visibleCount = 4;
} else if (breakpoint === "xl") {
  visibleCount = 5;
}
```

- [ ] **Step 2: Add container width state and ResizeObserver**

At the top of the `DataTableInner` function (after the existing `useState` calls), add:

```typescript
const [containerWidth, setContainerWidth] = useState(0);
const tableContainerRef = useCallback((node: HTMLDivElement | null) => {
  if (!node) return;
  const observer = new ResizeObserver(([entry]) => {
    setContainerWidth(entry.contentRect.width);
  });
  observer.observe(node);
  return () => observer.disconnect();
}, []);
```

Add `useCallback` to the import from `react` at the top of the file.

- [ ] **Step 3: Replace the column visibility useEffect**

Replace the entire `useEffect` block (lines 338-367) with:

```typescript
useEffect(() => {
  const allColumns = table.getAllColumns();
  const columnsId = allColumns.map((column) => column.id);

  // Width-aware column visibility
  // Fixed columns: select (~40px) + actions (~100px) = 140px
  // Minimum useful column width: 100px
  // Cell padding: 12px × 2 = 24px per column
  const fixedWidth = 140;
  const minColumnWidth = 100;
  const cellPadding = 24;
  
  const availableForData = Math.max(containerWidth - fixedWidth, 0);
  const maxDataColumns = containerWidth > 0
    ? Math.floor(availableForData / (minColumnWidth + cellPadding))
    : 5; // fallback for SSR
  
  // Clamp between 2 and all data columns
  const dataColumnCount = columnsId.filter(
    (id) => id !== "actions" && id !== "select"
  ).length;
  const visibleCount = Math.min(Math.max(maxDataColumns, 2), dataColumnCount);

  const visibility: VisibilityState = {};
  columnsId.forEach((id, index) => {
    if (id === "actions" || id === "select") {
      visibility[id] = true;
    } else {
      visibility[id] = index < visibleCount;
    }
  });

  setColumnVisibility(visibility);
}, [containerWidth, table]);
```

- [ ] **Step 4: Add ref to the table wrapper div**

Find the `<div className="flex-1 overflow-auto px-4">` (around line 569). Add the `ref`:

```tsx
<div ref={tableContainerRef} className="flex-1 overflow-auto px-4">
```

Run: `pnpm --filter frontend type-check`

Expected: No new errors.
